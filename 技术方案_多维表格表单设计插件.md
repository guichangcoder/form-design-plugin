# 多维表格表单设计插件 — 技术方案

## 1. 需求分析

### 1.1 核心目标
开发一个飞书多维表格插件，提供自定义表单界面，支持：
- **主子表联动录入**：在一个表单中同时填写主表和多个子表的数据
- **必填项控制**：可配置哪些字段必填，提交前校验
- **条件显示**：基于字段值动态显示/隐藏其他字段（如：选择"是"时显示附加字段）

### 1.2 典型场景
例如"客户拜访登记"：
- 主表：客户拜访记录（客户名、拜访时间、拜访人）
- 子表A：拜访事项（事项描述、完成状态）
- 子表B：费用记录（费用类型、金额）
- 条件显示：选择"有费用"时，才显示费用相关字段

## 2. 技术栈选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 框架 | React 18 + TypeScript | 官方模板默认，生态成熟 |
| 构建 | Vite 5 | 官方模板使用，开发热更新快 |
| SDK | `@lark-base-open/js-sdk` ^0.5.0 | 官方 SDK，提供 Base/Table/Field/Record/UI/Bridge 全套 API |
| UI 库 | Semi UI (`@douyinfe/semi-ui`) ^2.58 | 官方示例使用，飞书设计风格一致 |
| 国际化 | i18next + react-i18next | 官方模板内置，支持中英文切换 |
| 状态管理 | React Context + useReducer | 插件规模适中，无需引入 Redux |

### 2.1 插件类型选择

飞书多维表格有两种插件类型：

| 类型 | 入口 | API | 适用场景 |
|------|------|-----|----------|
| **侧边栏插件（扩展脚本）** | Base 侧边栏 | `bitable` 全套 API | 数据操作、表单录入 ✅ 推荐 |
| **仪表盘插件（应用插件）** | 仪表盘区域 | `dashboard` + `bitable` | 数据可视化、图表展示 |

**推荐：侧边栏插件（扩展脚本）**

理由：
1. 表单录入是交互式操作，用户在 Base 中直接打开侧边栏填写
2. 侧边栏插件有完整的 `bitable` API 访问权，可直接读写表数据
3. 开发和部署更简单：`npm run build` → 提交 dist + 填表单
4. 配置存储用 `bitable.bridge.setData/getData`，无需 dashboard 生命周期

## 3. SDK API 能力梳理

### 3.1 核心模块

```
bitable
├── base        — Base 级操作（获取表列表、创建/删除表、上传文件）
├── ui          — UI 交互（toast 提示、记录选择器、记录详情弹窗）
├── bridge      — 桥接能力（数据存储、语言/主题、用户信息）
└── [table]     — 通过 base.getActiveTable() 或 getTableById() 获取
    ├── field  — 字段操作（获取字段、创建 Cell、读写值）
    ├── record — 记录操作（通过 table.addRecord / addRecords 等）
    └── view   — 视图操作
```

### 3.2 本插件需要用到的关键 API

#### Base 模块 (`bitable.base`)
| 方法 | 用途 |
|------|------|
| `getTableList()` | 获取所有数据表列表（配置阶段选表） |
| `getTableById(id)` | 按 ID 获取表实例（写入数据时用） |
| `getTableByName(name)` | 按名称获取表实例 |
| `getSelection()` | 获取当前选中信息（默认选表） |
| `addTable({name})` | 创建新表（可选功能） |
| `batchUploadFile(files)` | 批量上传附件，返回 fileToken 列表 |

#### Table 模块
| 方法 | 用途 |
|------|------|
| `getFieldMetaList()` | 获取所有字段元信息（配置阶段选字段） |
| `getFieldMetaListByType(type)` | 按类型筛选字段 |
| `getField(idOrName)` | 获取字段实例（读写值时用） |
| `addRecord({fields})` | 新增单条记录，返回 recordId |
| `addRecords([record])` | 批量新增记录（上限 200 条/次） |
| `getRecordsByPage(params)` | 分页查询记录（回填编辑模式时用） |
| `setRecord(id, {fields})` | 更新记录（编辑模式用） |

#### Field 模块（按类型）
| 方法 | 用途 |
|------|------|
| `field.getValue(recordId)` | 获取记录中该字段的值 |
| `field.setValue(recordId, value)` | 设置记录中该字段的值 |
| `field.createCell(value)` | 创建 Cell 对象（用于 addRecord） |
| `field.getMeta()` | 获取字段元信息（类型、选项等） |

**单向关联字段 (SingleLink, FieldType=18) 专用方法：**
| 方法 | 用途 |
|------|------|
| `singleLinkField.createCell({recordIds: [...]})` | 创建关联单元格 |
| `singleLinkField.setValue(recordId, {recordIds: [...]})` | 设置关联值 |
| `singleLinkField.getTableId()` | 获取关联的目标表 ID |
| `singleLinkField.setTableId(tableId)` | 设置关联的目标表 |

#### Bridge 模块 (`bitable.bridge`)
| 方法 | 用途 |
|------|------|
| `setData(key, data)` | 存储插件配置（同一文档+插件共享） |
| `getData(key)` | 读取插件配置 |
| `getLanguage()` | 获取当前语言（初始化 i18n） |
| `getTheme()` | 获取主题（light/dark） |
| `onThemeChange(cb)` | 监听主题变化 |

#### UI 模块 (`bitable.ui`)
| 方法 | 用途 |
|------|------|
| `showToast({toastType, message})` | 显示提示（info/success/warning/error/loading） |
| `selectRecordIdList(tableId, viewId)` | 唤起记录选择器（关联字段录入用） |

## 4. 架构设计

### 4.1 三层架构

```
┌─────────────────────────────────────────────────────────┐
│  1. 配置层 (Configuration Layer)                         │
│  - 表选择：主表 + 子表                                   │
│  - 字段映射：可见性 + 必填标记                           │
│  - 条件规则：if-then 显示逻辑                            │
│  存储：bitable.bridge.setData / getData                 │
├─────────────────────────────────────────────────────────┤
│  2. 表单渲染层 (Form Rendering Layer)                    │
│  - 主表单区：渲染主表字段                                │
│  - 子表单区：渲染子表字段（可多条）                      │
│  - 条件显示引擎：根据当前值动态显示/隐藏字段              │
│  技术：React + Semi UI Form 组件                        │
├─────────────────────────────────────────────────────────┤
│  3. 数据写入层 (Data Writing Layer)                      │
│  - 校验必填项                                           │
│  - 先写主表记录 → 获取 recordId                          │
│  - 用 recordId 作为关联值写入子表记录                    │
│  - ui.showToast 反馈结果                                │
└─────────────────────────────────────────────────────────┘
```

```typescript
interface FormPluginConfig {
  // 版本号，便于后续迁移
  version: string;

  // 主表配置
  mainTable: {
    tableId: string;
    tableName: string;
    // 需要在表单中显示的字段（按顺序）
    fields: FieldConfig[];
  };

  // 子表配置（可多个）
  subTables: SubTableConfig[];

  // 条件显示规则
  conditionalRules: ConditionalRule[];

  // 表单标题和描述
  formTitle: string;
  formDescription?: string;
}

interface FieldConfig {
  fieldId: string;
  fieldName: string;
  fieldType: FieldType;
  // 是否在表单中显示
  visible: boolean;
  // 是否必填
  required: boolean;
  // 显示标签（可自定义，默认用字段名）
  label?: string;
  // 占位提示文字
  placeholder?: string;
  // 默认值
  defaultValue?: any;
  // 是否只读
  readonly?: boolean;
}

interface SubTableConfig {
  tableId: string;
  tableName: string;
  // 主子表关联字段（子表中的 SingleLink/DuplexLink 字段）
  linkFieldId: string;
  // 子表表单字段
  fields: FieldConfig[];
  // 是否允许添加多条子表记录
  allowMultiple: boolean;
  // 最多允许添加多少条
  maxRows?: number;
}

interface ConditionalRule {
  // 规则 ID
  ruleId: string;
  // 触发条件
  trigger: {
    tableId: string;      // 主表或子表的 ID
    fieldId: string;      // 触发字段 ID
    operator: 'equals' | 'notEquals' | 'contains' | 'isEmpty' | 'isNotEmpty';
    value: any;           // 比较值
  };
  // 满足条件时的动作
  actions: {
    type: 'show' | 'hide' | 'require' | 'unrequire';
    tableId: string;      // 目标表 ID
    fieldIds: string[];   // 目标字段 ID 列表
  }[];
}
```

## 5. 核心实现方案

### 5.1 模式切换

插件有两种模式，通过 `bitable.bridge.getData` 是否有配置来判断：

```typescript
// App.tsx
import { bitable } from '@lark-base-open/js-sdk';

function App() {
  const [mode, setMode] = useState<'config' | 'fill'>('fill');
  const [config, setConfig] = useState<FormPluginConfig | null>(null);

  useEffect(() => {
    bitable.bridge.getData('formConfig').then((saved: FormPluginConfig | null) => {
      if (saved) {
        setConfig(saved);
        setMode('fill');
      } else {
        setMode('config'); // 首次使用，进入配置模式
      }
    });
  }, []);

  if (mode === 'config') {
    return <ConfigPanel config={config} onSave={handleSave} />;
  }
  return <FormRenderer config={config!} onBackToConfig={() => setMode('config')} />;
}
```

```typescript
// 字段配置：获取选中表的字段列表
async function loadFields(tableId: string) {
  const table = await bitable.base.getTableById(tableId);
  const fieldMetaList = await table.getFieldMetaList();
  return fieldMetaList.filter(meta => {
    // 过滤掉只读字段（公式、自动编号、创建时间等）
    const readonlyTypes = [FieldType.Formula, FieldType.CreatedTime,
      FieldType.ModifiedTime, FieldType.CreatedUser,
      FieldType.ModifiedUser, FieldType.AutoNumber, FieldType.Lookup];
    return !readonlyTypes.includes(meta.type);
  });
}
```

```typescript
export function renderField(field: FieldConfig, value: any, onChange: (v: any) => void) {
  const commonProps = {
    value,
    onChange,
    placeholder: field.placeholder,
    disabled: field.readonly,
  };

  switch (field.fieldType) {
    case FieldType.Text:
      return <TextArea {...commonProps} autosize rows={2} />;

    case FieldType.Number:
    case FieldType.Currency:
      return <InputNumber {...commonProps} />;

    case FieldType.SingleSelect:
      return <Select {...commonProps} optionList={field.options} />;

    case FieldType.MultiSelect:
      return <TagInput {...commonProps} optionList={field.options} />;

    case FieldType.DateTime:
      return <DatePicker {...commonProps} type="dateTime" />;

    case FieldType.Checkbox:
      return <Switch checked={value} onChange={onChange} />;

    case FieldType.Phone:
      return <Input {...commonProps} prefix="+86" />;

    case FieldType.Url:
      return <Input {...commonProps} prefix="https://" />;

    case FieldType.Email:
      return <Input {...commonProps} prefix="@ " type="email" />;

    case FieldType.Attachment:
      return <Upload {...commonProps}
        action="" // 使用 bitable.base.batchUploadFile 代替
        beforeUpload={async (file) => {
          const tokens = await bitable.base.batchUploadFile([file]);
          onChange(tokens);
          return false; // 阻止默认上传
        }}
      />;

    case FieldType.SingleLink:
    case FieldType.DuplexLink:
      return <LinkFieldSelect {...commonProps}
        tableId={field.linkTableId}
      />; // 自定义组件，调用 bitable.ui.selectRecordIdList

    case FieldType.Rating:
      return <Rating {...commonProps} />;

    case FieldType.Progress:

    default:
      return <Input {...commonProps} />;
  }
```

### 5.4 必填项校验

```typescript
// utils/validator.ts
export function validateForm(
  config: FormPluginConfig,
  mainValues: Record<string, any>,
  subValues: Record<string, any>[]
): { valid: boolean; errors: string[] } {
  const errors: string[] = [];

  // 校验主表必填字段
  for (const field of config.mainTable.fields) {
    if (field.required && !mainValues[field.fieldId]) {
      errors.push(`主表「${field.fieldName}」为必填项`);
    }
  }

  // 校验子表必填字段（每条子表记录）
  for (let i = 0; i < subValues.length; i++) {
    const record = subValues[i];
    for (const subConfig of config.subTables) {
      for (const field of subConfig.fields) {
        if (field.required && !record[field.fieldId]) {
          errors.push(`子表「${subConfig.tableName}」第${i + 1}条：「${field.fieldName}」为必填项`);
        }
      }
    }
  }

  return { valid: errors.length === 0, errors };
}
```

### 5.5 条件显示引擎

```typescript
// hooks/useConditional.ts
export function useConditional(
  config: FormPluginConfig,
  mainValues: Record<string, any>,
  subValues: Record<string, any>[]
) {
  return useMemo(() => {
    const visibilityMap: Record<string, Set<string>> = {}; // tableId → 隐藏的 fieldIds
    const requiredOverrides: Record<string, Set<string>> = {};

    for (const rule of config.conditionalRules) {
      const { trigger, actions } = rule;
      // 获取触发字段的值
      const triggerValue = getFieldValue(trigger.tableId, trigger.fieldId,
                                         mainValues, subValues);
      const matched = evaluateCondition(trigger.operator, triggerValue, trigger.value);

      for (const action of actions) {
        if (!visibilityMap[action.tableId]) {
          visibilityMap[action.tableId] = new Set();
          requiredOverrides[action.tableId] = new Set();
        }
        for (const fieldId of action.fieldIds) {
          if (action.type === 'hide' && matched) {
            visibilityMap[action.tableId].add(fieldId);
          } else if (action.type === 'show' && !matched) {
            visibilityMap[action.tableId].add(fieldId);
          } else if (action.type === 'require' && matched) {
            requiredOverrides[action.tableId].add(fieldId);
          } else if (action.type === 'unrequire' && matched) {
            requiredOverrides[action.tableId].add(fieldId);
          }
        }
      }
    }

    return { visibilityMap, requiredOverrides };
  }, [config, mainValues, subValues]);
}

function evaluateCondition(operator: string, actual: any, expected: any): boolean {
  switch (operator) {
    case 'equals': return actual === expected;
    case 'notEquals': return actual !== expected;
    case 'contains': return Array.isArray(actual) && actual.includes(expected);
    case 'isEmpty': return !actual || actual === '' || actual === null;
    case 'isNotEmpty': return !!actual && actual !== '' && actual !== null;
    default: return false;
  }
}
```

### 5.6 数据写入 — 主子表关联写入

```typescript
// services/recordService.ts
import { bitable, FieldType, IOpenLink } from '@lark-base-open/js-sdk';

export async function submitForm(
  config: FormPluginConfig,
  mainValues: Record<string, any>,
  subRecords: Record<string, any>[] // 按子表分组
): Promise<{ success: boolean; mainRecordId?: string; error?: string }> {
  try {
    // Step 1: 写入主表记录
    const mainTable = await bitable.base.getTableById(config.mainTable.tableId);

    // 将表单值转换为 SDK 格式
    const mainFields = await convertToSdkFormat(
      config.mainTable.fields, mainValues, config.mainTable.tableId
    );

    const mainResult = await mainTable.addRecord({ fields: mainFields });
    const mainRecordId = (mainResult as any).recordId;

    // Step 2: 写入子表记录（带关联）
    for (const subConfig of config.subTables) {
      if (!subRecords[subConfig.tableId]?.length) continue;

      const subTable = await bitable.base.getTableById(subConfig.tableId);

      // 批量准备子表记录
      const subRecordsData = [];
      for (const record of subRecords[subConfig.tableId]) {
        const fields = await convertToSdkFormat(
          subConfig.fields, record, subConfig.tableId
        );
        // 设置关联字段指向主表记录
        fields[subConfig.linkFieldId] = {
          recordIds: [mainRecordId],
          text: '',
          tableId: subConfig.tableId,
        } as IOpenLink;
        subRecordsData.push({ fields });
      }

      // 批量写入（上限200条/次）
      const batchSize = 200;
      for (let i = 0; i < subRecordsData.length; i += batchSize) {
        const batch = subRecordsData.slice(i, i + batchSize);
        await subTable.addRecords(batch);
      }
    }

    // Step 3: 反馈
    await bitable.ui.showToast({
      toastType: 'success' as any,
      message: '提交成功',
    });

    return { success: true, mainRecordId };
  } catch (err) {
    await bitable.ui.showToast({
      toastType: 'error' as any,
      message: `提交失败: ${(err as Error).message}`,
    });
    return { success: false, error: (err as Error).message };
  }
}

// 将表单值转换为 SDK 格式
async function convertToSdkFormat(
  fields: FieldConfig[],
  values: Record<string, any>,
  tableId: string
): Promise<Record<string, any>> {
  const result: Record<string, any> = {};
  const table = await bitable.base.getTableById(tableId);

  for (const field of fields) {
    if (!values[field.fieldId]) continue;
    const fieldInstance = await table.getField(field.fieldId);
    const meta = await fieldInstance.getMeta();

    // 根据字段类型转换值
    switch (meta.type) {
      case FieldType.Attachment:
        // 附件值是 fileToken 列表
        result[field.fieldId] = { text: '', val: values[field.fieldId] };
        break;
      case FieldType.SingleSelect:
      case FieldType.MultiSelect:
        // 选项值直接传入
        result[field.fieldId] = values[field.fieldId];
        break;
      case FieldType.DateTime:
        // 日期转时间戳
        result[field.fieldId] = values[field.fieldId] ? +new Date(values[field.fieldId]) : null;
        break;
      default:
        result[field.fieldId] = values[field.fieldId];
    }
  }
  return result;
}
```

### 5.7 子表多条记录的 UI 交互

子表表单需要支持"添加行"和"删除行"的操作：

```typescript
// FormRenderer/SubForm.tsx
function SubForm({ config, values, onChange }: SubFormProps) {
  const [rows, setRows] = useState<Record<string, any>[]>([{}]);

  function addRow() {
    if (config.maxRows && rows.length >= config.maxRows) {
      bitable.ui.showToast({ toastType: 'warning', message: `最多${config.maxRows}条` });
      return;
    }
    setRows([...rows, {}]);
  }

  function removeRow(index: number) {
    setRows(rows.filter((_, i) => i !== index));
  }

  return (
    <Card title={config.tableName}>
      {rows.map((row, i) => (
        <div key={i} className="sub-form-row">
          {config.fields
            .filter(f => isFieldVisible(f.fieldId)) // 条件显示过滤
            .map(field => (
              <Form.Slot key={field.fieldId}
                label={field.label || field.fieldName}
                required={field.required}
              >
                {renderField(field, row[field.fieldId],
                  (v) => updateRow(i, field.fieldId, v))}
              </Form.Slot>
            ))}
          <Button icon={<IconClose />} onClick={() => removeRow(i)} />
        </div>
      ))}
      <Button onClick={addRow} icon={<IconPlus />}>添加一条</Button>
    </Card>
  );
}
```

## 7. 关键约束与注意事项

### 7.1 SDK 限制

| 限制 | 值 |
|------|-----|
| `addRecords` 单次上限 | 200 条 |
| `setRecords` 单次上限 | 200 条 |
| `deleteRecords` 单次上限 | 200 条 |
| `batchUploadFile` | 禁止并发调用，必须串行 |
| 附件文件名长度 | ≤ 250 字符 |
| 附件文件大小 | ≤ 2GB |
| `getRecordsByPage` 单次上限 | 200 条 |

### 7.2 只读字段（不可录入）

以下字段类型由系统自动生成，表单中应跳过：
- Formula (20) — 公式
- Lookup (19) — 查找引用
- CreatedTime (1001) — 创建时间
- ModifiedTime (1002) — 修改时间
- CreatedUser (1003) — 创建人
- ModifiedUser (1004) — 修改人
- AutoNumber (1005) — 自动编号
- Barcode (99001) — 二维码

### 7.3 主子表关联前提

主表和子表之间**必须已存在关联字段**（SingleLink=18 或 DuplexLink=21）。
- 在配置阶段，需要检测子表中是否有指向主表的关联字段
- 如果没有，需要提示用户先在多维表格中创建关联

### 7.4 事务性考虑

SDK 不支持事务。如果子表写入失败，主表记录已写入：
- **方案 A**：失败时删除主表记录（`table.deleteRecord(mainRecordId)`）
- **方案 B**：标记为部分成功，提示用户手动处理
- **推荐方案 A**，配合 toast 提示告知用户
